Writing Python Scripts

Author

Jason R. Wilson

A Python script is a text file containing Python code that can be executed as a program. Throughout these notes, we will use Python scripts to implement algorithms, process data, and perform numerical computations.

New to Python?

These notes assume previous programming experience. Familiarity with Python is helpful but not required. If you are new to Python, the official Python tutorial provides a good introduction to the language.

Our First Python Script

Consider the following Python code.

hello.py 
print("Hello World!")

Save this code in a text file named hello.py.

Creating a File in Google Colab

If you are using Google Colab, the %%writefile command can be used to write the contents of a code cell to a file.

For example, enter the following in a Colab code cell:

%%writefile hello.py
print("Hello World!")

Running the cell by clicking the Run cell button or pressing Shift+Enter creates the file hello.py.

We can run the script from a terminal using the Python interpreter.

$ python3 hello.py
Hello World!
Google Colab Terminal

To open a terminal in Google Colab, click the Terminal button at the bottom left of the window. This opens a Linux terminal that can be used to run the scripts created using %%writefile.

The Linux command

python3 hello.py

tells the Python interpreter to execute the instructions stored in the file hello.py.

Python scripts normally use the file extension .py.

Command-Line Arguments

A script becomes more useful when its behavior can depend on input provided by the user. One way to provide input to a script is through command-line arguments.

The variable sys.argv contains the command used to run the program. In particular, sys.argv[0] contains the name of the script, while sys.argv[1] contains the first command-line argument and so on.

The following Python script prints a personalized greeting.

greeting.py 
import sys

name = sys.argv[1]
print("Hello", name)

We can now provide a name when we run the program.

$ python3 greeting.py Watson
Hello Watson

Command-line arguments are Python strings. If a command-line argument represents a number, we need to explicitly convert it.

For example, the following script computes the square of its integer input.

square.py 
import sys

n = int(sys.argv[1])
print(n,"squared =",n*n)
$ python3 square.py 12
12 squared = 144

Note that Python integers can be arbitrarily large.

$ python3 square.py 12345678987654321
12345678987654321 squared = 152415789666209420210333789971041

Multiple Command-Line Arguments

A script can accept an arbitrary number of command-line arguments. The function len can be used to determine the number of entries in sys.argv.

Recall that sys.argv[0] contains the name of the script. Therefore, the command-line arguments begin at sys.argv[1] and the number of command-line arguments is len(sys.argv) - 1.

The next script computes the average of an arbitrary number of floating-point values provided on the command-line.

average.py 
import sys

n = len(sys.argv)
total = 0.0
for i in range(1, n):
    total += float(sys.argv[i])
average = total / (n - 1)

print("Average =", average)
$ python3 average.py 1.5 2.5 4.0 8.0
Average = 4.0

Creating Strings

Many computing tasks require the creation of text.

Python strings are immutable, which means that individual characters cannot be changed after a string has been created. For example, the following code is not allowed.

word = "python"
word[0] = "P"  # this line will cause an error
print(word)

Python lists, on the other hand, are mutable. We can therefore convert the string to a list, modify its individual characters, and then use join() to convert the list back into a string.

word = list("python")
word[0] = "P"  # this is legal Python
print("".join(word))

The following script creates an acronym by combining the first letter of each command-line argument. Note that we use result = [" "]*(n-1) to initialize a list that will hold the eventual acronym.

acronym.py 
import sys

n = len(sys.argv)
result = [" "]*(n-1)
for i in range(1,n):
    result[i-1] = sys.argv[i][0].upper()

print("".join(result))
$ python3 acronym.py high performance computing
HPC

Reading Text from Files

In the examples that follow, we will work with words from the game Wordle.

If you are unfamiliar with Wordle, take a few minutes to play the game before continuing.

The file legal_words.txt contains a collection of five-letter words that are legal inputs to Wordle. To download the file, copy and paste the following wget command into a Linux terminal and run it.

wget https://raw.githubusercontent.com/jasonrwilson/hpc_notes/main/N01/legal_words.txt

The following Linux commands show the number of lines in the file and the first 5 lines.

$ wc -l legal_words.txt
14818 legal_words.txt
$ head -5 legal_words.txt
aahed
aalii
aapas
aargh
aarti

The file legal_words.txt contains 14,818 legal Wordle input words, with one word per line.

The next script checks whether a word given as a command-line argument is a legal Wordle input.

After opening the file containing the legal words, the script scans the file one line at a time. The strip() method removes leading and trailing whitespace—including the newline character at the end of each line—before the word is compared with the guess.

Once a match is found, the break statement immediately terminates the for loop since there is no reason to examine the remaining words.

legal.py 
import sys

guess = sys.argv[1]
f = open("legal_words.txt","r")
found = False

for line in f:
    word = line.strip()
    if word == guess:
        found = True
        break

f.close()
if found:
    print(guess, "is legal")
else:
    print(guess, "is not legal")
$ python3 legal.py crane
crane is legal

$ python3 legal.py abcde
abcde is not legal

Wordle Starting Words

A good Wordle starting word should contain letters that are likely to appear in the hidden word.

We can assign a score to each possible starting word by looping over all possible hidden words and adding one point for each character of the hidden word that matches the starting word in the same position.

For example, when computing the score of the potential starting word slate, the legal word stare contributes 3 points because the two words have the same letter in three positions.

The following script computes this score for the word given as a command-line argument. We added error handling to ensure that the given starting word satisfies the requirements of the scoring algorithm. The function sys.exit(1) terminates the script with a nonzero exit status, indicating that an error occurred.

score.py 
import sys

if len(sys.argv) != 2:
    print("error: expected one starting word")
    sys.exit(1)

start = sys.argv[1]

if len(start) != 5:
    print("error: starting word must have 5 letters")
    sys.exit(1)

for c in start:
    if c < "a" or c > "z":
        print("error: starting word must contain all lowercase letters")
        sys.exit(1)

f = open("legal_words.txt","r")

score = 0

for line in f:

    word = line.strip()
    for i in range(len(word)):
        if start[i] == word[i]:
            score += 1

f.close()
print ("score =",score)

Let’s first verify the error handling of our script.

$ python3 score.py
error: expected one starting word
$ python3 score.py cat
error: starting word must have 5 letters
$ python3 score.py sLeep
error: starting word must contain all lowercase letters

Here are our scores for the popular starting words adieu and slate.

$ python3 score.py adieu
score = 4763
$ python3 score.py slate
score = 6576

According to our scoring method, slate is the better starting word.

One approach to finding the starting word with the highest score is to read all of the legal words into a list and then score each possible start word, keeping track of the best score as we go.

Here is a script that implements this approach. We use a helper function score to calculate the score of a given start word.

start.py 
def score(start,words):
    score = 0
    for word in words:
        for i in range(len(word)):
            if start[i] == word[i]:
                score += 1
    return score

f = open("legal_words.txt", "r")

words = []

for line in f:
    words.append(line.strip())

f.close()

best_start = ""
best_start_score = -1

for start in words:
    start_score = score(start,words)
    if start_score > best_start_score:
        best_start_score = start_score
        best_start = start

print("best starting word =", best_start)
print("score =", best_start_score)

We use the Linux command time to measure how long the script takes to execute.

$ time python3 start.py
best starting word = sanes
score = 12304

real   1m20.492s
user   1m19.584s
sys    0m0.043s

The script finds sanes with a score of 12,304, but requires around 80 seconds to run (the real time is the total wall time).

There are 14,818 possible starting words. For each starting word, the script compares its five characters with all 14,818 legal words. Thus, the program performs \(O(n^2)\) work where \(n\) is the number of legal words.

A Better Algorithm

To understand why start.py is not efficient, consider scoring the two possible starting words slate and stare.

When scoring slate, the program scans all 14,818 legal words to determine how often s appears in position 0, how often l appears in position 1, how often a appears in position 2, and so on.

When the program later scores stare, it again scans all 14,818 legal words. In particular, it recomputes how often s appears in position 0, how often a appears in position 2, and how often e appears in position 4, even though these quantities were already computed while scoring slate.

Instead of repeatedly scanning all 14,818 legal words for each possible start word, we can make one pass through the legal words and count how often each of the 26 letters occurs in each of the five positions. Once these counts have been computed, the score of any word requires only five table lookups.

The function ord() returns the Unicode code point for a character. Since the lowercase English letters a through z have consecutive code points, the following helper function index maps the lowercase letters to the integer indices 0 through 25.

def index(c):
    return ord(c) - ord("a")

We can therefore store the positional counts in a 5-by-26 list of lists which we create using:

num = [[0]*26 for i in range(5)]

for word in words:
    for i in range(5):
        num[i][index(word[i])] += 1

For example, after running the above code, num[1][2] contains the number of times the letter c occurs in the second position, since index("c") = 2.

The following script uses this precomputed table idea to determine the best starting word in only \(O(n)\) work.

fast_start.py 
def index(c):
    return ord(c) - ord("a")

f = open("legal_words.txt", "r")

words = []

for line in f:
    words.append(line.strip())

f.close()

n = len(words)

# find the number of times each letter
# appears in each position
num = [[0]*26 for i in range(5)]

for word in words:
    for i in range(5):
        num[i][index(word[i])] += 1

best_start_word = ""
best_start_score = -1

for start in words:

    start_score = 0
    for i in range(5):
        start_score += num[i][index(start[i])]
    if start_score > best_start_score:
        best_start_score = start_score
        best_start_word = start

print("best starting word =", best_start_word)
print("score =", best_start_score)
$ time python3 fast_start.py
best starting word = sanes
score = 12304

real   0m0.085s
user   0m0.076s
sys    0m0.008s

Both scripts produce the same result, but fast_start.py is dramatically faster. We can quantify the improvement using speedup, defined as

\[ \text{speedup} = \frac{\text{original wall time}} {\text{improved wall time}} \]

The wall time for start.py was \(80.492\) seconds.

The wall time for fast_start.py was \(0.085\) seconds. Therefore, the speedup is

\[ \text{speedup} = \frac{80.492}{0.085} \approx 947 \]

Thus, fast_start.py is approximately 947 times faster than start.py.

No parallel computing or specialized hardware was required to obtain this speedup. Both programs are written in Python and produce exactly the same result. The improvement comes from changing the algorithm so that information that was repeatedly recomputed is instead computed once and reused.

The idea of eliminating redundant computation appears throughout high-performance computing and machine learning. For example, backpropagation, the fundamental algorithm used to train neural networks, efficiently computes gradients by reusing intermediate results rather than repeatedly recomputing the same quantities.
